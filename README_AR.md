# FirstAidProject — نسخة مراجَعة

## ما الذي تم إصلاحه؟

- تصحيح ملف `render.yaml` وإضافة مسار الفحص `/api/health` الذي كان إعداد النشر يشير إليه دون وجود route.
- إضافة وظائف إضافة وتعديل وحذف لجهات الاتصال والعيادات وقواعد الإسعافات من لوحة الأدمن.
- إضافة أزرار تحرير وحذف ونوافذ تعديل داخل لوحة الأدمن الحالية، مع الإبقاء على تصميمها الأساسي.
- جعل حفظ بيانات العيادات يحترم أعمدة `clinics.csv` بدلاً من كتابة سبعة حقول غير متوافقة مع ملف ذي ثمانية أعمدة.
- حماية عمليات الكتابة والتعديل والحذف بتسجيل دخول الأدمن، وإضافة CSRF token لنماذج الإدارة وطلبات التعديل.
- تحسين كتابة ملفات CSV وJSON باستخدام حفظ ذري لتقليل احتمال تلف الملف إذا فشل الحفظ في منتصف العملية.
- إبقاء ملف البيانات الأصلي دون تغييره أثناء الاختبارات؛ اختبارات CRUD أُجريت على نسخ مؤقتة.
- إصلاح ترميز فتح سجل البحث عند الإضافة لتجنب إضافة BOM جديد عند كل عملية بحث.

## التشغيل محليًا على Windows

1. فكّي ملف ZIP في مجلد جديد. لا حاجة لنسخ مجلد `.venv`؛ يجب إنشاء بيئة محلية على الجهاز نفسه.
2. افتحي PowerShell في مجلد المشروع.
3. أنشئي البيئة وفعّليها (إذا لم تكن لديك بيئة جاهزة):

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

4. ثبتي المكتبات:

   ```powershell
   python -m pip install -r requirements.txt
   ```

5. انسخي `.env.example` إلى `.env`، ثم افتحي `.env` وعدّلي القيمتين `ADMIN_PASSWORD` و`FLASK_SECRET_KEY` لقيم خاصة بك. لا ترفعي ملف `.env` إلى GitHub.

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

6. شغّلي التطبيق:

   ```powershell
   python app.py
   ```

7. افتحي `http://127.0.0.1:5000/login` وسجّلي الدخول بكلمة المرور التي وضعتها في `.env`. لوحة الأدمن: `http://127.0.0.1:5000/admin`.

## كلمة السر وحماية لوحة الأدمن

- صفحة `/admin` ومسارات الإدارة (`/api/dashboard/*` و`/api/entities` و`/api/import` و`/api/analytics`) لا يدخلها إلا من سجّل الدخول من `/login` بكلمة السر.
- كل عمليات الإضافة والتعديل والحذف تتطلب تسجيل الدخول + CSRF token.
- المسارات العامة (يستخدمها التطبيق): قراءة `/api/rules` و`/api/contacts` و`/api/clinics`، والبحث `/api/search`.
- كلمة السر تُضبط بالمتغير `ADMIN_PASSWORD` (والمفتاح السري `FLASK_SECRET_KEY`) ولا تُكتب داخل الكود. للتشغيل المحلي في ملف `.env`، وعلى Vercel من إعدادات المشروع.
- بعد الخروج بالرابط `/admin/logout` لا يمكن فتح اللوحة إلا بكلمة السر من جديد.

## النشر على Vercel من GitHub

1. ارفعي محتوى مجلد `FirstAidProject` (الذي فيه `app.py`) إلى جذر مستودع GitHub. لا ترفعي `.env` (مستثنى في `.gitignore`).
2. في Vercel: **Add New → Project** ثم اختاري المستودع. سيتعرّف Vercel على Flask تلقائيًا (لا حاجة لأي إعداد للبناء).
3. قبل الضغط على Deploy افتحي **Environment Variables** وأضيفي:
   - `ADMIN_PASSWORD` = كلمة السر التي تريدينها
   - `FLASK_SECRET_KEY` = نص عشوائي طويل (يمكن توليده بالأمر: `python -c "import secrets; print(secrets.token_hex(32))"`)
4. اضغطي Deploy ثم افتحي الرابط: سيحوّلك إلى `/login`.
- ملفات الواجهة (CSS/JS) موجودة في مجلد `public/` لأن Vercel يخدمها من هناك، وFlask يخدمها محليًا من نفس المجلد.
- إذا نسيتِ أحد المتغيرين سيفشل التشغيل برسالة واضحة في سجلات Vercel (Logs).
- **مهم:** نظام ملفات Vercel للقراءة فقط. لوحة الأدمن والبحث والعرض تعمل، لكن إضافة/تعديل/حذف البيانات لن تُحفظ هناك، وتظهر رسالة واضحة بذلك، وتسجيل البحث يُتجاوز بصمت. التعديل الدائم يعمل عند التشغيل محليًا. للحفظ الدائم على Vercel يلزم ربط قاعدة بيانات (مثل Neon أو Supabase).

## حدود المراجعة

- تم التحقق من صياغة ملفات Python وJavaScript، وقوالب Flask، وإعداد YAML، واختبار تسجيل الدخول ومسارات القراءة وعمليات CRUD باستخدام `Flask test_client` ونسخ مؤقتة من ملفات البيانات.
- محرك البحث الحالي يطابق النصوص داخل قواعد `rules.json` بكلمات الاستعلام. لا يطبّق حتى الآن inverted index أو TF-IDF أو cosine similarity، ولا توجد في الملفات الحالية مجموعة منفصلة من أدلة الإسعافات النصية؛ إذا كانت هذه عناصر مطلوبة في rubric المشروع فستحتاج تنفيذًا إضافيًا.
- معلومات الإسعافات الأولية ينبغي مراجعتها بواسطة مختصين، كما تشير الملاحظة داخل لوحة الإدارة.
